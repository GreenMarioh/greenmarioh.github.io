# Portfolio Content Repositioning and Implementation Brief

## Context

I have an existing personal portfolio website for Mohnish Kumar / GreenMario.

The current website has a strong visual identity and a technical, systems-oriented aesthetic, but its content positioning does not accurately reflect my primary professional profile.

The current site over-indexes on:

- Software-Defined Networking
- ML-based SDN load balancing
- Networking research terminology
- C/C++ as the dominant identity
- The SDN project as the central "signature architecture"

This creates an inaccurate or at least unnecessarily narrow first impression.

My actual profile is broader and should primarily position me as a **Software Engineer / Systems & Backend Engineer with strong CS fundamentals and practical experience across backend systems, developer tooling, ML/AI, automation, and infrastructure**.

Networking and machine learning are important parts of my profile, but they should support the broader engineering identity rather than define it completely.

The redesign should therefore be primarily a **content architecture and positioning correction**, not a complete visual redesign.

---

Do NOT make the portfolio look like I am primarily an academic ML researcher or SDN researcher.

# 2. Problem With the Current Hero

The current hero says:

> "Systems, ML and networks. Built to anticipate load, not react to it."

This is technically interesting but too narrow.

It makes the entire portfolio sound like it revolves around predictive SDN load balancing.

The hero should instead establish me as a software engineer first.

A better conceptual direction is something like:

> Software Engineer building systems, backend infrastructure, and intelligent tools.

or:

> Software Engineer focused on systems, backend engineering, and intelligent software.

The exact wording can be refined to match the existing visual style.

The important thing is that:

**Software engineering comes first.**

Systems, ML, networking, cybersecurity, etc. should appear as areas I work across.

Avoid making the hero sound like a PhD thesis abstract.

# 16. Important Content Rule

Do not invent achievements, metrics, production scale, performance improvements, users, traffic, or technical details.

Where existing descriptions contain claims such as:

> "zero queue backlog"

> "continuous deterministic throughput"

> "3-5s prediction"

> "large-scale"

> "production"

verify that the implementation genuinely supports those claims.

If a claim is unsupported, rewrite it conservatively.

The portfolio should be impressive because the engineering is real, not because the copywriter discovered adjectives.

---

Do NOT turn this into a generic developer portfolio.

The existing technical aesthetic is valuable.

Preserve:

- Dark visual system
- Green accent
- Terminal/system aesthetic
- Monospace typography where appropriate
- Technical metadata
- Architecture diagrams
- Section numbering
- GitHub links
- Interactive elements
- Subtle telemetry/system motifs

The design should feel like:

**a technically sophisticated engineer's portfolio**

rather than:

**a fake spacecraft control panel containing a resume.**

---

# 18. Content Tone

Use concise, technically credible writing.

Avoid generic phrases such as:

- "passionate developer"
- "tech enthusiast"
- "innovative solutions"
- "leveraging cutting-edge technologies"
- "transforming ideas into reality"

Prefer concrete statements describing:

- what was built
- why it was built
- architecture
- engineering decisions
- constraints
- technologies
- measurable outcomes when verified

Each project should answer:

```text
What is it?
Why does it exist?
What did I build?
What engineering problem did I solve?
What technologies were involved?
What makes the project technically interesting?
```
